## Release gate

The disposable VM gate passed for OVMF/systemd-boot loading the production 6.18.54 UKI, initramfs unlocking LUKS2, expected Btrfs subvolume mounts, systemd `running`, and configured-user console login. It also passed for the source-built 7.2.10 experimental UKI after correcting the stale rehearsal target's missing systemd `cryptsetup` USE flag: the initramfs unlocked LUKS2, all four Btrfs subvolumes mounted, systemd reached `running`, and the configured `rehearsal` user logged in over SSH. The initial failed source-UKI attempt and successful repeat are documented in the evidence README and `gentoo-experimental-first-boot-verification.log`; the full source build log is `experimental-kernel-source-build.log.gz`. A separately verified Gentoo LiveGUI image booted through OVMF from USB, reached KDE, acquired DHCP, and ran the installer's read-only inventory against a disposable qcow2 target; the configured physical identity guard refused the QEMU disk. This did not proceed to storage authorization or installation. Follow-up QEMU boots confirmed the production default and isolated fallback entry reach the LUKS2 prompt. A synthetic failed production image was rolled back and the restored default booted to the prompt. The guarded rollback CLI also passed against a real disposable mounted root/ESP on Linux, including invalid-image replacement and wrong-serial refusal; it has not run inside the booted Gentoo VM and no reboot followed that invocation. The disposable LUKS negative-unlock test, storage-stage loop rehearsal, read-only rescue fixture recovery, wrong-identity refusal, and file-level kernel rollback integration tests passed. Do not install on a physical drive yet. Booted independent recovery media and restore from an independent backup, full installation from live media, executing rollback inside Gentoo with a follow-up reboot, and hardware-dependent checks remain open. The project is **not production-ready**.
